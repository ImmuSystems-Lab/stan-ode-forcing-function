# Using forcing functions in ordinary differential equations (ODE) in Stan

This GitHub pages website
explains how to use forcing functions in ODEs
in Stan as well as lower-level ODE solvers
and be accessible to both human readers as well as AI coding agents.

<https://immusystems-lab.github.io/stan-ode-forcing-function>

## Contributing code

When writing your git commit message,
please follow the NumPy guidelines[^np-commit].

When modifying the CI build,
test on your own local container
so that you can interactively debug issues
before running GitHub Actions.

> [!TIP]
> Choosing local container software for your operating system:
> If you don't currently have software installed to run a container,
> consider use a rootless container provider
> to limit security exploits from misconfiguration.
>
> - On GNU/Linux operating systems you may consider
>   [containerd/nerdctl](https://github.com/containerd/nerdctl).
> - On macOS you may consider
>   [apple/container](https://github.com/apple/container).
> - On Windows,
>   there currently doesn't appear to be a rootless container system;
>   therefore, consider using
>   [Docker Desktop](https://www.docker.com/products/docker-desktop/).
>   Once you install Docker Desktop,
>   you additionally need to "Enable Docker terminal"[^docker-shell-windows]
>   from the UI to launch containers from the shell
>   to follow along with the commands below.

The existing CI commands are in
[`.github/workflows/render.yml`](https://github.com/ImmuSystems-Lab/stan-ode-forcing-function/blob/main/.github/workflows/render.yml)
Test changes to CI with:

```bash
# Only if you are on GNU/Linux:
#
alias docker=nerdctl

# Only if you are on macOS:
#
alias docker=container

docker pull rocker/verse:latest
docker run -it rocker/verse:latest bash
# - In the command above, make sure to specify `bash` as the program to run,
#   otherwise the container will launch a Posit RStudio session.  If that
#   happens hit Ctrl+C to kill the process and type `exit` to kill the container
#   and rerun the above command with the trailing `bash` command.
#
# - Make a note of the autogenerated hostname of your new container, namely,
#   if your prompt looks something like:
#
#     root@268e36bf7a7b:/#
#
#   ... that would mean your hostname is 268e36bf7a7b that we will refer to as
#   HOSTAME in the next command.

# In a shell outside the container, create a zip file of this repository
# containing any changes you've made.  Then copy that container from your
# host computer into the container with:
#
docker cp path/to/your/stan-ode-forcing-function.zip HOSTNAME:/tmp
# ... where HOSTNAME is the randomly generated characters from your prompt,
# described above.

# Optional: If you are using GNU/Linux or macOS, you can use this one-liner
# to both create the zip file and copy it to your most recently launched
# container when run from somewhere in your git tree:
#
src=$(basename $(git rev-parse --show-toplevel))
pushd $(git rev-parse --show-toplevel) > /dev/null &&
    git ls-files |
        xargs zip -r /tmp/${src}.zip &&
    docker cp /tmp/${src}.zip $(docker ps -l --format '{{json .ID}}' | jq -r):/tmp/ &&
    popd > /dev/null

# Back in the shell running your container, extract the zip file:
#
cd                  # Goes to your home directory instead of / (root).
unzip /tmp/stan-ode-forcing-function.zip

# Now you will have the same starting environment as GitHub Actions.
# You can run subsequent CI commands such as the following,
# described in the render.yml file, modifying any steps as needed:
#
Rscript -e 'pak::local_install_deps("stanodeffr", dependencies = TRUE)'
Rscript -e 'tinytex::tlmgr_install("amsfonts")'
Rscript -e 'rmarkdown::render(Sys.glob("*/*.Rmd"),
            output_format = "all",
            output_dir = "public")'
cd public/
apt update && apt -y install tree
ls -d *_files |
    xargs printf "-I %s " |
    xargs \
        tree -H '.' \
        -T 'Vignettes for Stan ODE forcing function' \
        --noreport \
        --houtro "" \
        -o index.html \
        -I index.html

# When you are done with your container, shut it down to release the resources:
exit
```
